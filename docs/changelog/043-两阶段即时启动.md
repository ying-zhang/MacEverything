# 043 - 两阶段即时启动

- **类型**: feature
- **日期**: 2026-04-15
- **Commit**: `5eda742` (merge), branch commit: `6335447`

## 问题描述

应用启动时，若 FSEvents 回放失败，会丢弃已持久化的索引数据，回退到全量磁盘扫描，耗时 50 秒以上。用户在此期间无法进行任何搜索操作，体验极差。

## 修复/实现方案

实现两阶段启动策略：

**Phase 1 — 即时加载**：
- 从持久化文件加载索引数据
- 立即交付给 UI 层，用户可以马上开始搜索（基于上次退出时的索引）

**Phase 2 — 后台同步**：
- 通过 FSEvents 回放增量更新索引
- 若 FSEvents 回放失败，回退到全量扫描，但不影响 Phase 1 已交付的搜索能力

附带修复：
- 将 `InstanceLock.cpp/.h` 添加到 Xcode 项目（R3 合并时遗漏）
- 将 R3-1 实例锁集成到启动流程中

## 影响的文件

- `MacEverything/Bridge/MacSearchBridge.mm` — 两阶段启动流程编排
- `MacEverything/Core/SearchEngine.cpp` — 索引加载与后台同步逻辑
- `MacEverything.xcodeproj/project.pbxproj` — 添加 InstanceLock 文件引用
