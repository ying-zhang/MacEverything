# 029 - 基于标题的窗口查找替代类型判断

- **类型**: bugfix
- **严重级别**: P1-HIGH
- **日期**: 2026-04-14
- **Commit**: `176c569` (merge), branch commit: `4792116`

## 问题描述

通过快捷键或其他方式激活应用窗口时，可能错误地聚焦到设置窗口而非主搜索窗口。

## 根因分析

`AppDelegate` 和 `HotkeyManager` 使用 `!($0 is NSPanel)` 来查找主窗口。这种基于类型的判断方式存在缺陷：当设置窗口（Settings window）不是 `NSPanel` 子类时，它同样会通过过滤条件，导致返回设置窗口而非主搜索窗口。共有 4 处窗口查找逻辑存在此问题。

## 修复/实现方案

- 在应用启动时通过标题匹配（"MacEverything"）捕获主搜索窗口引用，存储为属性
- 所有 4 处窗口查找逻辑改为引用该存储属性，消除基于类型的不可靠判断
- `HotkeyManager` 的 C 回调函数改为基于标题的窗口查找

## 影响的文件

- `AppDelegate.swift`
- `HotkeyManager` 相关文件

## 测试覆盖

- 验证快捷键激活时始终聚焦主搜索窗口
- 验证设置窗口打开时快捷键行为正确
