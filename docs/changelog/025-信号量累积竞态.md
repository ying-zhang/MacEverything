# 025 - 信号量累积竞态

- **类型**: bugfix
- **严重级别**: P0-CRITICAL
- **日期**: 2026-04-14
- **Commit**: `d538a99` (merge), 分支提交: `f696b9f`

## 问题描述

内容索引信号量 `_contentIndexingSemaphore` 在多次索引完成后失去阻塞能力，后续等待立即返回，导致索引并发控制完全失效。

## 根因分析

`_contentIndexingSemaphore` 在初始化时创建一次，初始计数为 0。每次索引完成时调用 `signal` 使计数加 1。经过 N 次完成后，信号量计数累积到 N。此后所有 `wait` 调用立即返回（计数 > 0），无法阻塞，信号量形同虚设。

这是一个典型的信号量语义误用：将一次性同步原语当作可复用的门控使用。

## 修复/实现方案

在每次 `wait` 返回后重新创建信号量（初始计数 0），彻底排空累积的信号。确保下一轮等待能够正确阻塞直到新的 `signal` 到来。

## 影响的文件

- `MacEverything/Core/ContentIndexPersistence.h` / `.cpp`
- `MacEverything/Bridge/SearchBridge.mm`

## 测试覆盖

- 多轮索引完成后信号量仍能正确阻塞的测试
- 快速连续 signal/wait 序列的正确性验证
- 并发索引场景下的竞态测试
