# 045 - 重扫防抖与节流

- **类型**: bugfix
- **严重级别**: P1-HIGH
- **日期**: 2026-04-15
- **Commit**: `3ea3a4f`

## 问题描述

FSEvents 的 `MustScanSubDirs` 事件（通常 path="/"）会触发立即全盘重扫。在实际使用中，这类事件每 3-5 分钟发生一次，导致频繁的全盘扫描，严重消耗 CPU 和 I/O 资源，影响系统性能和用户体验。

## 根因分析

`MustScanSubDirs` 是 FSEvents 在事件队列溢出时发出的粗粒度通知，表示需要重新扫描指定子目录树。由于未做任何去重、防抖或节流处理，每次事件都直接触发完整的磁盘遍历操作。频繁的短间隔事件导致重扫操作几乎连续执行。

## 修复/实现方案

实现纯 C++ 的 `RescanDebounce` 工具类，包含三层防护：

1. **5 秒防抖定时器**：累积事件，每次新事件到达时重置定时器，等待事件流稳定后再触发重扫
2. **路径包含关系合并（Subsumption）**：当同时收到 `/Users` 和 `/` 的重扫请求时，合并为仅扫描 `/`，避免重复扫描
3. **300 秒节流**：同一路径在 300 秒内最多触发一次重扫，防止高频重复扫描
