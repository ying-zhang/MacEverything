# 155 — 连续输入候选复用与匹配阶段 Top-K

普通文件名查询在继续打字时会保留上一轮的全部命中记录号，下一轮只要能证明查询范围变小，就只重验这批记录。界面请求的 `maxResults + 1` 不再当作下一轮的候选。OR、NOT、通配符、正则、过滤器、大小写或拼音开关变化、Unicode 第二形态、系统应用别名，以及任何索引变更，都不复用。

变更代次在新增、删除、更新、重扫、WAL 回放、加载和压实时增加。它和会话取消代次、压实代次分开。命中超过 200 万条时不写入缓存。

扫描线程只保留最好的 `maxResults` 条，缓冲区达到两倍上限后用 `nth_element` 截断，再合并排序。这不减少匹配次数。同分时记录号较小的排在前面。

## 测试

`test_all --part 82` 覆盖截断窗口外的命中、追加词、回删、换序、过滤器、大小写、新增文件、压实，以及 Top-K 和同分顺序。
