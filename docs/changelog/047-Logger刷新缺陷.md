# 047 - Logger 刷新缺陷

- **类型**: bugfix
- **严重级别**: P2-MEDIUM
- **日期**: 2026-04-15
- **Commit**: `6fcf500` (merge), branch commit: `8707928`

## 问题描述

运行时 INFO 级别的日志全部停留在 libc 缓冲区中，从未写入磁盘文件。导致运行时诊断信息不可见，无法通过日志文件排查问题。

## 根因分析

`kFlushInterval=32` 设置意味着每 32 次写入才执行一次 `fflush`。由于 INFO 日志的产生频率较低，缓冲区在达到 32 次写入阈值前始终不会被刷新。加上 libc 的 FILE 缓冲（通常 4KB-8KB），低频日志可能在整个应用生命周期内都停留在内存缓冲区中，进程正常退出时才可能刷出，异常退出则完全丢失。

## 修复/实现方案

改为每次写入后立即执行 `fflush`。

理由：日志的写入频率足够低（非高频热路径），per-write fflush 带来的性能开销可以忽略不计。日志的可观测性远比微小的 I/O 优化更重要。

## 影响的文件

- `MacEverything/Core/Logger.h` — 移除 kFlushInterval，改为每次写入刷新

## 测试覆盖

- 验证日志写入后立即可在文件中读取到
- 日志写入性能无显著回归
