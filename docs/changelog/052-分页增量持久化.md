# 052 - 分页增量持久化

- **类型**: performance
- **日期**: 2026-04-15
- **Commit**: `56b9d66`

## 问题描述

全量快照式压缩每次都需要将所有记录（约 112MB）完整写入磁盘，即使绝大多数记录未发生变更。频繁的全量写入带来高 I/O 负载、写放大和页缓存污染。

## 修复/实现方案

用分页增量写入替代全量快照压缩，实现按需持久化：

**PagedIndexWriter**：
- 双文件格式：`.pages`（数据页）+ `.ptable`（页表/元数据）
- 每页包含 CRC32 校验和，支持损坏检测
- 仅写入脏页，典型 flush I/O 从 ~112MB 降至 KB 级别

**脏页跟踪**：
- SearchEngine 维护脏页位图（bitmap）
- 每页包含 1024 条记录
- 记录变更时标记对应页为脏

**自适应压缩间隔**：
- 基于脏页比例和 WAL 大小动态调整间隔
- 范围：30 秒（高变更率）至 600 秒（低变更率）
- WAL 大小触发器：WAL 超过 2MB 时立即 flush

**死空间回收**：
- 当页文件中废弃空间超过 50% 时触发 `fullRewrite`
- 完全重建页文件，消除碎片

**版本迁移**：
- V3 → V4 自动迁移
- 保留旧版 index.bin 作为备份
- 迁移失败时可回退

## 影响的文件

- `MacEverything/Core/PagedIndexWriter.h` — 分页写入器定义
- `MacEverything/Core/PagedIndexWriter.cpp` — 分页写入/读取/CRC 校验实现
- `MacEverything/Core/SearchEngine.cpp` — 脏页跟踪与自适应压缩调度
- `MacEverything/Core/SearchEngine.h` — 脏页位图与新接口声明
- `MacEverything/Core/IndexWAL.cpp` — WAL 大小触发器集成
