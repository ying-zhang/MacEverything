# 031 - P2 级别批量修复

- **类型**: bugfix
- **严重级别**: P2-MEDIUM
- **日期**: 2026-04-14
- **Commits**: `2b1c559`, `ccee7f7`, `80de5e6`, `bda0802`

## 问题描述

多项 P2 级别问题和 Minor 级别改进的批量修复，涵盖帮助文本、废弃代码、日志、状态管理、权限检测等方面。

## 根因分析

各项问题的根因：

- **P2-9**: `--fast` 模式帮助文本描述不准确
- **P2-7**: 存在未使用的 `Window("Shortcut Settings")` scene 定义
- **P2-3**: `--fast` 模式遗漏了 Part 7e/7f 的跳过逻辑
- **P2-6**: `RegisterEventHotKey` 失败时无日志输出，难以诊断快捷键注册问题
- **P2-8**: generation 不匹配时 `isLoadingMore` 未重置，导致加载状态卡住
- **M-1**: `ContentIndex.indexFile` 中存在冗余的二进制文件检查（`readFileIfText` 已包含 NUL 检测）
- **M-5**: `PermissionView` 在用户授予 FDA（Full Disk Access）权限后需要重启应用才能检测到
- **M-4**: `ContentSettingsView` 点击 Apply 总是触发重建，即使配置未实际变更

## 修复/实现方案

- **P2-9**: 更新 `--fast` 帮助文本，准确描述跳过的步骤
- **P2-7**: 移除未使用的 `Window("Shortcut Settings")` scene
- **P2-3**: 在 `--fast` 模式中增加 Part 7e/7f 的跳过逻辑
- **P2-6**: 在 `RegisterEventHotKey` 失败时增加 NSLog 输出
- **P2-8**: 在 generation 不匹配时重置 `isLoadingMore` 状态
- **M-1**: 移除 `ContentIndex.indexFile` 中冗余的二进制文件检查
- **M-5**: 在 `PermissionView` 中增加每 3 秒的 FDA 轮询检测，授权后自动继续，无需重启
- **M-4**: 在 `ContentSettingsView` 的 Apply 操作中增加脏检查（dirty check），仅在 extensions 或 maxFileSizeMB 实际变更时才触发重建

## 影响的文件

- CLI 帮助文本相关文件
- App scene 定义文件
- `HotkeyManager` 相关文件
- 搜索结果加载状态管理文件
- `ContentIndex` 索引文件
- `PermissionView.swift`
- `ContentSettingsView.swift`

## 测试覆盖

- 验证 `--fast` 模式正确跳过所有预期步骤
- 验证 FDA 轮询检测在权限授予后正确响应
- 验证 Apply 脏检查逻辑在配置未变时不触发重建
