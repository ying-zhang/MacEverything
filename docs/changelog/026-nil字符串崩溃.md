# 026 - nil 字符串崩溃

- **类型**: bugfix
- **严重级别**: P1-HIGH
- **日期**: 2026-04-14
- **Commit**: `e2b2f56` (merge), 分支提交: `90b8155`

## 问题描述

应用在扫描某些旧版 HFS+ 卷时崩溃，抛出 `NSInvalidArgumentException`，堆栈指向 `addObject:` 调用。

## 根因分析

macOS 的 HFS+ 遗留卷可能包含非 UTF-8 编码的文件名（如 MacRoman、Shift-JIS 等历史编码）。当使用 `[NSString stringWithUTF8String:]` 转换这些文件名时，返回 `nil`。随后将 `nil` 传入 `[NSMutableArray addObject:]` 触发 `NSInvalidArgumentException` 异常，导致应用崩溃。

这是 Objective-C 与 C 字符串交互的经典陷阱：`stringWithUTF8String:` 的 nil 返回值未被检查。

## 修复/实现方案

在所有 `stringWithUTF8String:` 调用后添加 nil 检查。当转换失败时，跳过该文件条目并记录日志，而非崩溃。这确保了非 UTF-8 文件名不会中断扫描流程。

## 影响的文件

- `MacEverything/Bridge/SearchBridge.mm`
