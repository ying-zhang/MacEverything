# 050 - COW 无阻塞压缩

- **类型**: performance
- **日期**: 2026-04-15
- **Commit**: `1e6d82b` (merge), branch commit: `f7ec620`

## 问题描述

`compactRecords()` 在重建 4.4M 条记录的索引结构期间持有 `unique_lock` 长达 30-60 秒，导致所有查询请求阻塞，实测观测到 15 秒以上的查询超时。

## 修复/实现方案

采用三阶段 Copy-on-Write (COW) 策略，将排他锁持有时间从 30-60 秒降至 100ms 以内：

**Phase 1 — 快照（shared_lock, ~200ms）**：
- 在共享锁下快速复制当前记录数据的快照
- 不阻塞并发读查询

**Phase 2 — 离线构建（无锁, ~30s）**：
- 在锁外基于快照构建压缩后的数据结构
- 完全不影响并发查询

**Phase 3 — 原子交换（unique_lock, <100ms）**：
- 获取排他锁
- 用新结构替换旧结构
- 回放 Phase 2 期间积累的中间变更（intermediate mutations）
- 释放锁

新增静态方法：
- `buildTrigramIndexFromData()` — 从数据构建 trigram 索引（可在锁外调用）
- `buildRecentCacheFromData()` — 从数据构建最近缓存（可在锁外调用）

## 影响的文件

- `MacEverything/Core/SearchEngine.cpp` — 三阶段 COW 压缩实现
- `MacEverything/Core/SearchEngine.h` — 新增静态构建方法声明

## 测试覆盖

- Phase 2 期间查询不阻塞的并发测试
- 中间变更正确回放的验证
- COW 压缩后索引与全量重建结果一致性
- Phase 3 排他锁持有时间 <100ms 的性能验证
