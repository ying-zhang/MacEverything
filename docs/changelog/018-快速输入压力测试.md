## 问题描述

缺乏对用户快速输入场景的自动化压力测试，无法量化搜索延迟、取消率和资源消耗，难以发现输入抖动引发的并发问题。

## 修复/实现方案

实现 Part 19 压力测试套件，模拟多种真实输入模式：

- **增量输入**（Incremental typing）：逐字符追加，模拟正常打字。
- **清除并重新输入**（Clear + retype）：模拟用户清空搜索栏后重新输入。
- **突发输入**（Burst typing）：短时间内快速输入大量字符。
- **Scenario 5**：CPU 冷却检测 — 在 `FileSystemWatcher` 活跃期间验证 CPU 使用率能回落到合理水平。

测试基础设施：
- 使用 100K 条记录的数据集。
- 通过 `getrusage` 监控 CPU 和内存消耗。
- 测量每次搜索的延迟和取消率指标。

## 影响的文件

- `tests/test_part19_rapid_typing.h`
- `tests/test_all.cpp`

## 测试覆盖

- 增量输入延迟 < 阈值验证
- 突发输入下的取消率统计
- CPU/内存在压力后的回落检测
- FileSystemWatcher 不引入额外 CPU 开销验证
