# 021 - 焦点感知的索引刷新节流

- **类型**: bugfix
- **严重级别**: P1-HIGH
- **日期**: 2026-04-14
- **Commit**: `f09e314` (merge), 分支提交: `50c69bb`

## 问题描述

即使应用窗口不在前台，FSEvents 持续触发索引刷新和搜索，导致后台 CPU 持续消耗，影响系统其他应用的性能。

## 根因分析

FSEvents 监听根路径 "/" 时，系统进程的文件操作会持续产生事件，每 2 秒触发一次 `O(n)` 的全量查询。即使用户未使用应用，后台仍在不断消耗 CPU 资源执行无意义的搜索。

## 修复/实现方案

通过 `NSApplication` 追踪窗口焦点状态，实现三级节流策略：

- **未聚焦（Unfocused）**：完全跳过索引刷新，不执行任何搜索操作。
- **重新聚焦（Focus regain）**：执行一次追赶刷新（catch-up），确保数据与文件系统同步。
- **已聚焦（Focused）**：将刷新节流间隔从 2 秒放宽到 5 秒，降低前台 CPU 消耗。

## 影响的文件

- `MacEverything/Bridge/SearchBridge.mm`
- `MacEverything/App/AppDelegate.swift`（或相关焦点监听逻辑）

## 测试覆盖

- 焦点状态切换逻辑单元测试
- 未聚焦期间无刷新验证
- 重新聚焦后追赶刷新触发验证
- 节流间隔正确性测试
