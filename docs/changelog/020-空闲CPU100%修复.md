# 020 - 空闲状态 CPU 100% 占用

- **类型**: bugfix
- **严重级别**: P0-CRITICAL
- **日期**: 2026-04-14
- **Commit**: `2c045af` (merge), 分支提交: `3093483`

## 问题描述

应用在空闲状态下 CPU 占用率达到 100%，严重影响系统整体性能和用户体验，尤其在笔记本上导致电池快速耗尽和风扇高速运转。

## 根因分析

`rescanSubtree` 在处理文件系统变更时，对每个变更文件逐一调用 `removeTrigramsForRecord`。该函数对每个 trigram 执行 `O(N)` 的 `vector::erase` 操作（N 为 posting list 长度，可达 100K+）。

当 K 个文件变更、每个文件有 T 个 trigram 时，总复杂度为 **K x T x O(N) memmove**，导致灾难性的 CPU 消耗。

## 修复/实现方案

- **batchRescanPrefix()**：替代逐文件处理方式。对旧记录标记墓碑（tombstone），追加新记录，最后一次性重建 trigram 索引。相比逐一删除，实现 **82 倍**加速。
- **FSEvents 排除**：将应用缓存目录加入 FSEvents 排除列表，避免自身写入触发无效重扫。
