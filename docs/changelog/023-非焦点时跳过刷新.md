# 023 - 未聚焦时跳过刷新消除 CPU 消耗

- **类型**: bugfix
- **严重级别**: P1-HIGH
- **日期**: 2026-04-14
- **Commit**: `ed049dc` (merge), 分支提交: `9e86254`

## 问题描述

应用在未聚焦状态下仍然消耗约 100% CPU，焦点感知节流未完全生效。

## 根因分析

虽然 021 引入了焦点感知逻辑，但 FSEvents 触发的回调仍会调用 `performSearch`，其中 `dispatch_apply` 会在所有 CPU 核心上并行执行搜索。`performIndexRefresh()` 路径缺少 `isFocused` 检查，导致即使应用未聚焦，昂贵的搜索操作仍然全速执行。

## 修复/实现方案

- 在 `performIndexRefresh()` 入口处添加 `isFocused` 守卫检查。
- 未聚焦时直接跳过整个搜索流程，包括 `dispatch_apply` 并行搜索。
- 重新聚焦时执行一次追赶刷新（catch-up），保证数据时效性。

## 影响的文件

- `MacEverything/Bridge/SearchBridge.mm`

## 测试覆盖

- 未聚焦状态下 `performIndexRefresh` 不触发搜索验证
- 聚焦恢复后追赶刷新正确执行验证
- CPU 占用率在未聚焦状态下回落到接近 0 的回归测试
