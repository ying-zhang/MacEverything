# 006 - 12 项性能优化

- **类型**: performance
- **日期**: 2026-04-14
- **Commit**: `b284ae3`（合并 perf/trigram-index 分支）

## 问题描述

初始实现存在多个性能瓶颈，包括 O(N) 线性搜索、过多的内存消耗、不必要的锁竞争、冗余 I/O 等。

## 实现方案

| # | 优化项 | 效果 |
|---|--------|------|
| 1 | 文件名搜索添加 trigram 倒排索引 | 4.5x 加速 |
| 2 | 有 maxResults 限制时用 `partial_sort` | 1.4x 排序加速 |
| 3 | 消除 `lowerPaths_` 冗余存储 | ~55MB 内存节省 (1M 记录) |
| 4 | 搜索期间减少 `shared_mutex` 竞争 | 降低锁等待 |
| 5 | SwiftUI row `.id()` 移除 searchText | 避免全列表重建 |
| 6 | WAL fsync 批量化 | 减少 I/O 开销 |
| 7 | 扫描器批量推送子目录 | 减少锁竞争 |
| 8 | 二进制检查与文件读取合并为单次 I/O | 减少系统调用 |
| 9 | `removeByPathPrefix` 单次遍历 | 消除双重查找 |
| 10 | posting list 排序 + `set_intersection` | O(n+m) 集合交集 |
| 11 | 轻量 `recentIndices()` 访问器 | 避免 N 次拷贝 |
| 12 | `dispatch_apply` 并行生成 snippet | 利用多核 |
