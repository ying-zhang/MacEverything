# MacEverything 当前主分支审查

**状态**：1.10.20（构建号 14）正式发布审查记录；1.5.30 保留为历史正式版本

**更新时间**：2026-10-21

本文是当前代码状态的审查入口。历史审查中的问题只有在这里明确标记为“仍存在”或“已缓解”时，才应作为当前结论使用；提交说明、旧实验和历史数据请分别查看变更日志与基准目录。

## 当前结论

当前主分支的核心索引、FSEvents、内容索引、HTTP 和 UI 测试已通过。最近一轮审查发现的生命周期问题已处理：

- 网络轮询只处理网络文件系统根，并通过进行中标志避免扫描任务堆积。
- 首次扫描遇到不可达根时报告启动失败，不创建空的持久化索引，也不替换已有 engine。
- 监控重启沿用 watcher 的 FSEvents 水位；水位为零时仍从 `SinceNow` 启动，避免无意义的全量历史回放。
- HTTP 内容查询同时检查客户端断开、服务停止和 30 秒请求截止时间，并把取消回调传给内容索引验证循环。
- 网络文件系统判断先使用目标路径的 `statfs`，路径尚不存在时再按最长挂载点查询 mount table。
- 混合本地目录与 NAS 目录时，NAS 只走轮询重扫，本地目录仍按已保存水位回放 FSEvents。
- 重建索引会在删除旧索引前校验所有配置根目录，扫描失败会清除重建状态并显示具体原因。
- 高亮正则使用保守的语法守卫，拒绝嵌套量词和重复交替；拒绝只影响高亮，不影响 RE2 搜索结果。

## 发布前复审

本轮复查覆盖构建/签名/打包链路与 CI、应用和 MCP 版本来源、单实例锁、索引与监听生命周期、WAL/快照持久化、HTTP 安全边界、UI 异步结果/导出，以及文档发布状态和本地链接；结合静态分析与自动化回归，不代表对所有运行环境作无缺陷保证。

- **应用版本**：正式记录仅保留 1.5.30 和 1.10.20。旧阶段发布说明改为无版本号开发记录，避免暗示不存在的正式发布；第三方依赖、操作系统、协议及索引格式版本不作应用版本清理。
- **启动修复**：RE2/Abseil 静态链接，保留 Hardened Runtime 与库验证。用户于 2026-10-21 确认上一测试包在另一台 Mac 上不再闪退；这只覆盖启动反馈，不代表所有 GUI 操作或原生 Intel 已验收。
- **MCP 版本不一致**：初始化响应不再使用独立硬编码版本，而读取应用 Bundle；没有 Bundle 的独立 helper 返回 `unknown`，不伪造应用版本。新增打包 helper 和独立 helper 的实际 JSON-RPC 回归测试。
- **锁元数据越界读取**：`snprintf` 返回的是完整输出所需长度，可能大于固定缓冲区；原实现直接把该长度传给 `write`。现将写入长度限制在缓冲区有效字节内，补充超长版本字符串测试，并由 AddressSanitizer 验证。
- **文档护栏**：`make lint-docs` 自动核对应用版本、发布说明文件名、说明文件是否存在及本地 Markdown 链接，另有 7 项护栏回归测试。
- **构建与部署文档**：项目指南补齐 CMake、静态依赖准备、产物验证与官方 DMG 打包入口；历史动态库构建示例明确标为历史环境，不作为当前构建指引。
- **候选包身份**：版本维持 1.10.20，本轮因代码修正将构建号更新为 14。用户已确认的包是上一构建，本轮产物另行执行自动化与本机安装副本检查。

复审阶段没有创建提交或发布；2026-10-21 用户随后授权正式发布，同步 GitHub Release、网站下载页与 Homebrew Cask。历史身份候选已在发布前报告，新提交统一使用 GitHub noreply 身份；保留既有公开历史，不重写或强推。正式发布使用本轮已验证的构建号 14 安装包。

## 仍需关注

### 静态分析提示与故障路径

`xcodebuild analyze` 完成，但仍有 15 条分析器提示：3 条无效赋值、1 条 token 文件锁内读取、3 条 errno/rewind 相关提示及 8 条 FlatIndexWriter 写失败后的文件位置提示。已人工复查相关路径：token 文件锁用于跨进程串行化；快照写入会在 `ok` 失败时清理临时文件而不是发布该文件，但失败后仍查询文件位置的流程可进一步收紧。这些提示不是本次 dyld 闪退的根因，也不应一概标成误报或声称已清零；磁盘故障注入和失败路径整理仍值得后续补充。

### 性能断言的环境敏感性

并行执行双架构构建与快速测试时，`batchRescanPrefix` 的墙钟性能比较曾失败；停止并行编译后，串行快速测试通过。保留失败日志，没有放宽阈值或修改搜索算法。性能结果应在空闲机器上复核，正确性测试通过不等于所有负载下的性能都有保证。

### 高亮正则的边界

SwiftUI 高亮仍使用 ICU，而搜索使用 RE2。语法守卫是尽力而为的保护措施，不是复杂度证明，可能拒绝安全模式，也不能证明所有 ICU 模式都线性。长期方案是复用 RE2 的匹配结果，或将高亮匹配移出主线程并增加超时隔离。

### HTTP 查询的资源上限

内容查询已有 30 秒请求截止时间和客户端断开检测；文件读取仍受内容索引的最大文件大小和结果上限约束。若未来开放更大的结果上限，应重新评估 worker 占用和 NAS 延迟。

### 查询语法转义边界

`regex:` 放在查询末尾是已确认的设计约束；带转义引号或 `!` 的路径表达式仍有解析边界，后续若扩展 CLI、MCP 或 GUI 语法，应补充统一的转义规则和回归测试。

### FSEvents 与 NAS 的验证

本地测试覆盖 watcher 水位、扫描失败和 HTTP 安全路径；此前已通过 Windows SMB 共享完成基础扫描与同步验证。吞吐、断线重连、权限变化和挂载点切换仍应在 Windows SMB 测试机或实际 NAS 上进行长时间测试。

## 已确认的设计约束

- `regex:` 会消费剩余查询文本，以支持包含空格和 `|` 的正则表达式；因此它应放在查询末尾。该行为由 `tests/test_query_modifiers.h` 覆盖，不属于当前回归。
- `DirectoryScanner::isComplete()` 对请求根不可达保持失败语义。首次扫描和后台重建的处理不同：首次扫描报错并停止初始化，后台重建保留现有索引。
- HTTP 服务只绑定回环地址；认证、Host、Origin 和请求体校验由 `HttpServer` 统一处理。

## 历史审查要点

以下结论来自已合并的历史审查快照。它们保留值得注意的检查意见和处置结果，旧行号与旧测试数字不再作为当前依据。

| 主题 | 主要检查意见 | 当前状态 |
|---|---|---|
| 启动与索引生命周期 | 不完整扫描不能落盘为空索引；重建不能在根目录不可用时先删旧索引；Phase 2 交换需防止压缩期间使用陈旧快照 | 已修复；当前失败会保留可用 engine，重建先做根目录预检 |
| NAS 与 FSEvents | 网络根不应触发本地目录全量重扫；混合根目录应让本地回放水位、NAS 走轮询；监控重启需保留事件水位 | 已修复；Windows SMB 已完成基础扫描与同步验证 |
| 持久化安全 | StringPool 损坏条目边界、WAL 长度上限、CRC 与撕裂写入恢复需要一致性保护 | 已修复并由持久化测试覆盖 |
| 查询与 Unicode | CJK 扩展区、拼音回退、多音字、过滤器边界、日期月末和大小开放区间曾有召回或解析风险 | 已修复；仍需以查询回归测试为准 |
| 候选集与内容索引 | 路径 trigram 候选不能漏掉仅在路径中命中的记录；超长关键词不能让摘要窗口停滞 | 已修复并加入查询/内容测试 |
| FSEvents CI | `IgnoreSelf`、符号链接路径和临时目录选择导致集成测试在 CI 中失败 | 已修复；相关 Part 4、6、76 和全量测试已恢复 |
| 正则高亮与 HTTP 取消 | ICU 高亮需拒绝高风险回溯形状；内容查询需响应客户端断开、服务停止和请求截止时间 | 已修复；安全守卫可能保守拒绝模式，HTTP 半关闭仍是低风险边界 |

历史审查还确认了若干基础组件的差分测试结果：posting list、trigram、SIMD、WAL/CRC、日期比较、HTTP token 和内容索引映射未发现错误。后续审查应优先关注真实 NAS 长时间运行，以及网络轮询、水位恢复和 HTTP 取消的自动化护栏。

## 验证命令

```bash
scripts/prepare-re2-deps.sh
make test-fast
make test-asan
make test-tsan
xcodebuild -scheme MacEverything -configuration Release build
scripts/build-release-dmgs.sh
```

本轮串行 `make test-fast` 的核心测试为 **1924 passed / 0 failed**，Swift、Bridge、本地化、文档/版本护栏和签名回归测试通过。`make test-asan` 与 `make test-tsan` 各 **1924 passed / 0 failed**，未报告 sanitizer 错误。arm64 和 x86_64 Release 构建成功；签名/加载回归测试各 7 项通过，Intel 在 Rosetta 下运行。Xcode 报告本机 CoreSimulator 版本不匹配和 AppIntents 元数据跳过，不影响 macOS 构建；静态分析提示单独列于本页，不宣称零告警。

使用包内 MCP helper 执行 `make test-all`，默认完整核心套件 **12385 passed / 0 failed**。构建号 14 的两个最终 DMG 均完成只读挂载、复制安装、版本/架构/签名检查、隔离用户目录下 GUI 运行 8 秒、CLI 帮助和 MCP 初始化版本检查；包内 MCP 协议测试各 **45 passed / 0 failed**。这些检查不替代原生 Intel、其他 macOS 版本或真实 NAS 的人工验收。

`tests/test_review_regressions.h` 已覆盖多项根目录预检、扫描失败、生命周期代际、陈旧事件、重建监听水位、卷身份及缓存隔离路径，不能再笼统称为“没有自动化覆盖”。真实 NAS 断线、重连、吞吐和长期运行仍需专门环境验证；已有 Windows SMB 基础测试不替代这类验收。

发布构建完成后，按项目说明将 `.app` 和 `.dmg` 放入 `artifacts/`。真实 NAS 性能应记录扫描时长、增量延迟、重扫次数、内容索引吞吐、CPU、内存和断线恢复时间。
